\noindent\textit{Note.}
All 35 tasks have automated software-level scoring tests. Tasks marked
$^\dagger$ also have tests covering additional task behaviour such as trial
generation or difficulty adjustment. These tests verify implementation
correctness but do not establish psychometric or clinical validity. The
psychometric properties of the NeuroBloom task implementations have not yet
been established.

\section*{Software verification and testing}

NeuroBloom is tested with two automated suites. The backend suite contains
103 pytest tests: 31 numerical scoring fixtures, one for each backend-scored
task; 43 behavioural tests of trial generation, response classification, and
difficulty adjustment; 6 checks of the 35-task inventory; 7 checks of the
analytics parameters and sensitivity results; 15 API tests of authentication
and clinician endpoints; and one integration test of the patient--clinician
workflow. The frontend suite contains 20 Vitest tests covering the four
client-side scoring functions, task navigation, the baseline workflow, and
progress summaries.

The integration test exercises the complete workflow through the application
programming interface: patient registration and login; clinician
registration, administrator approval, and login; the patient's request to a
clinician and its approval; submission of the six baseline tasks, baseline
calculation, and training-plan generation; completion of a four-task training
session, including difficulty adaptation; and retrieval of the patient's
overview, session history, and trends by the clinician. It also confirms that
a clinician without an approved assignment cannot access the patient's
record.

Both suites run on every push and pull request through GitHub Actions
(Ubuntu, Python 3.12, Node.js 20). The backend tests use an in-memory SQLite
database in place of PostgreSQL. At the time of revision, all 123 tests passed
(Windows 10, Python 3.13, Node.js 22). The frontend tests target scoring and workflow modules; the Svelte page
components are not unit-tested, and browser-level end-to-end tests are not yet
included.

\section*{Reproducibility procedure}

The manuscript demonstration can be reproduced from the repository with Docker
Compose; the containers use Python 3.12, Node.js 20, and PostgreSQL 16. After
the provided environment template (\texttt{.env.example}) is copied to
\texttt{.env.local}, the PostgreSQL database, FastAPI backend, and Svelte
frontend are built and started with \texttt{compose.yaml}. The database and
cognitive-task library are initialized with \texttt{seed\_initial\_data.py}, and
\texttt{scripts/seed\_demo\_clinical\_data.py} generates a synthetic
demonstration dataset of eight clinicians and eight patients with baseline
assessments, training plans, repeated training sessions with contextual
records, progress reports, and risk alerts. The script uses a fixed random seed
to reproduce the same synthetic patient profiles and performance values; record
dates are generated relative to the execution date, so dashboard contents that
depend on recent activity differ between runs.

The patient--clinician workflow described in the manuscript can then be followed
in the application at \url{http://localhost:8080} with the demonstration
accounts: the patient completes baseline and training tasks, and the clinician
reviews the baseline, session history, trends, and longitudinal analytics.
Representative analytics outputs are regenerated with
\texttt{scripts/fatigue\_proxy\_sensitivity.py} and
\texttt{scripts/trend\_sensitivity.py}, which reproduce the sensitivity results
in Table~\ref{tab:sensitivity} and write them as JSON files to
\texttt{analysis/results/}. The complete commands are given in the repository
README. The demonstration accounts are intended for local use only.
